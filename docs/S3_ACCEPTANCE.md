# S3 구현과 검증

## 범위

- 원본 녹음 오디오와 원본 전사, 모드별 기준으로 구조화 피드백 생성. 원본 인용 검증, 강점 1~3개·교정 0~3개·영어 개선 예문·다음 연습.
- 수정 전사는 저장하지만 원본 평가 입력으로 사용하지 않음. 발음·억양·속도·멈춤은 오디오에서 들린 특징을 정성적으로 코칭한다. 구간·확신 수준을 표시하고 원본 구간 듣기를 제공한다. 공인 발음 점수·OPIc 등급은 생성하지 않는다.
- 미국식(en-US)·영국식(en-GB) 연습 기준은 기기에 기억하고 분석마다 스냅샷으로 저장한다. 어휘·철자·발음 연습 방향과 지역 음성 선택에 반영하며 다른 억양을 오류로 간주하지 않는다. 분석·음성 캐시는 발화와 발음 기준별로 분리한다.
- 분석 결과·근거·모드·원본 스냅샷·루브릭 버전 보존. 중복 탭은 기존 분석 반환. 실패만 최대 3회 시도, 사용자당 하루 20회 예약 제한.
- 예문은 필요할 때 Vertex TTS로 생성해 비공개 WAV로 캐시. 5분 만료 재생 URL, 기기에서 0.8/1/1.2배 재생. 음성 실패가 텍스트 피드백을 막지 않음.
- 세션별 피드백 이력·재열람, 피드백만 삭제, 녹음·전사·피드백·생성 음성을 포함한 연습 기록 삭제.
- 서버의 진행 중 상태를 저장하고 동시 요청에는 202를 반환. 실제 공급자 호출은 Vercel 요청 생명주기 안에서 최대 90초 기다림. 별도 작업 큐 없이 응답 이후 프로세스 지속을 가정하지 않음. 중단된 작업은 3분 후 제한 재시도 가능.

기본 공급자는 Vertex AI `gemini-3.5-flash`(코칭), `gemini-3.8-flash-lite-tts`(예문 음성)이며 `COACH_MODEL`·`TTS_MODEL` 환경 변수로 변경할 수 있다. 기존 `GOOGLE_API_KEY` 서버 인증을 재사용하며 사용량은 과금될 수 있다.

오디오는 소유권과 SHA-256을 확인한 비공개 녹음 바이트를 `audio/mp4` inlineData로 전달한다. 음성을 읽지 못하면 분석 실패로 남기며 전사만으로 자동 대체하지 않는다. 음성 품질이 부족하거나 전사가 불일치하면 관찰·교정을 보류한다. 예문 음성은 기본 음색 Kore에 `speechMetadata.style`로 미국식·영국식 발화를 요청한다. API 키 인증으로 401을 반환하는 Voices 목록 조회는 사용하지 않는다. 실제 억양 일치와 음성 품질은 실청취로 확인해야 한다. 지역별 검증 음색을 확보하면 `TTS_VOICE_EN_US`·`TTS_VOICE_EN_GB`로 지정할 수 있다.

공식 형식은 [오디오 이해](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/audio-understanding), [구조화 출력](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output)과 [Gemini TTS](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/text-to-speech/overview)를 기준으로 한다.

## 자동 검증

`cd apps/api && .venv/bin/python -m pytest -q`에서 24개 테스트로 원본 오디오 입력·체크섬, JSON 스키마·근거·구간 범위, 음성 목록 조회 없이 지역별 발화 지시·원문 분리, 다른 사용자 차단, 캐시 중복 호출 방지, 실패 상태 보존, WAV 변환, 단기 URL, Storage 실패 시 삭제 중단을 검증한다.

`supabase/tests/s3_coaching.sql`은 실제 DB에서 예약 중복 방지·원본 보존·짧은 발화 거부·RLS·클라이언트 RPC 실행 차단·이력 삭제 후에도 유지되는 일일 사용량 제한을 검증하고 모두 롤백한다. 테스트 데이터를 유지하지 않는다.

`evals/coaching_cases.json`은 실제 모델 결과를 사람이 비교할 대표 사례다. 오디오 코칭을 실행할 때는 각 문장을 실제로 읽은 녹음도 준비해야 하며, 전사 텍스트만으로 음성 품질을 검증하지 않는다. 자동 테스트 통과만으로 실제 코칭 품질을 승인하지 않는다. 원본 인용 일치, 의미 보존, 모드 적합성, 불필요한 교정, 민감한 추론·등급·음성 평가가 없는지 확인한다.

## Android 실기기 확인

1. 설정 탭에서 미국식·영국식을 선택하고 8단어 이상 녹음·전사 → 녹음 듣고 코칭 받기 → 내용·음성 피드백과 원본 구간 듣기 확인.
2. 인식 오류 수정본을 저장한 뒤에도 분석에 사용한 원본이 유지되는지 확인.
3. AI 예문 듣기·일시정지·재생 속도 변경. 음성 생성 실패해도 텍스트 예문이 보이는지 확인.
4. 화면을 나갔다 돌아와서 같은 피드백을 확인. 다시 누를 때 중복 분석을 만들지 않는지 확인.
5. 삭제 확인 창에서 취소·확인. 피드백만 삭제하면 원본 유지, 연습 기록 삭제 시 전체 이력 제거 확인.

iOS는 구현만 유지하고 실기기 테스트는 Android 우선 검증 후 진행한다. 실제 공급자 오디오 코칭·미국식/영국식 TTS 품질과 Android 구간 재생은 기기 확인 전까지 미검증이다.

## 아이콘

`assets/icon.png`와 투명 `assets/adaptive-icon.png`는 제공된 Tinkit Studio 이미지를 바탕으로 ImageGen으로 제작했다. 블랙 배경, 실버 수달, 민트 말풍선을 사용한다. Android 아이콘 설정은 새 APK에 포함되므로 기존 설치본은 OTA로 화면 기능만 받을 수 있다.


## 탭·설정 Android 확인

- 로그인·Google 로그인·기존 세션 복원 후 대시보드 진입, 로그아웃 후 로그인 화면 복귀.
- 하단 네 탭 표시, 오픽·회화별 시나리오 분리, 기존 연습 이력 접근.
- 설정에서 영어 기준 저장 → 오픽/회화 연습 화면과 새 분석에 적용. 기존 피드백의 기준은 보존.
- 설정의 마이크 사용 허용 버튼으로 최초 시스템 권한 팝업 확인.
- 설정에서 미리 허용하지 않은 경우에도 시나리오 시작에서 권한 요청. 거부하면 세션을 만들지 않음.
- OS에서 다시 요청할 수 없는 경우 기기 설정으로 안내. 복귀 후 설정 화면의 상태 갱신.
- 허용된 마이크를 OS에서 취소한 뒤 기존 세션에서 녹음 시작 시 다시 권한 절차 안내.

탭 이동·권한 거부·기기 설정 복귀와 OAuth는 Android 실기기 확인이 필요하다. 타입 검사와 Android 내보내기로 전체 라우트가 컴파일되는지 확인한다.

## 재생 오류 수정 검증

- Android 원본 재생은 최초 로딩 후 한 번만 탐색한다. 탐색 중 `isLoaded`가 바뀌어도 재생을 취소하거나 다시 탐색하지 않는다. 전체 원본은 불필요한 0초 탐색을 생략한다.
- 원본 로딩·재생·일시정지·실패를 표시하고, 20초 로딩 지연을 안내한다. AI 음성도 최초 한 번만 자동 재생하며 네이티브 재생 오류를 표시한다.
- 수정 후 API 테스트 24개, 모바일 타입 검사, Android 번들 생성 통과. 운영 API 배포 완료(`dpl_GKRC4UD5DuhTPphYaU5pGWYkzK1h`), `/health` 정상. 배포 빌드에서 실제 서버 키로 테스트 문장 음성 생성 성공: en-US 163,228바이트, en-GB 153,628바이트. 기기 재생과 억양 품질은 아직 미검증. Android OTA preview/runtime 0.1.0 게시 완료(그룹 `75091fa8-343d-4660-ab64-91e7a54312fd`).
