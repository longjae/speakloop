# 문장 따라하기

코칭 결과의 ‘개선 예문 듣기’ 화면에서 ‘한 문장씩 듣고 따라하기’를 누른다.

1. 최대 12문장을 한 문장씩 표시한다.
2. 예문 듣기. 분석에 저장된 미국식·영국식 기준으로 생성하며 0.8/1/1.2배 속도를 선택한다.
3. 따라 녹음한 뒤 내 목소리를 듣는다. 예문과 번갈아 듣고 강세와 끊어 읽기 한 가지를 비교한다.
4. 다음 문장으로 이동한다. 녹음은 1초 이상이어야 하며 이전 문장도 다시 연습할 수 있다.

따라하기의 녹음은 업로드하지 않는다. 화면을 나가면 이 연습에서 만든 파일을 삭제한다. 앱 강제 종료 시 운영체제 파일 정리가 늦어질 수 있다. 이 기능은 듣기·비교 연습이며 자동 발음 점수나 문장별 AI 평가는 제공하지 않는다.

## 서버

문장 목록과 본문은 소유권이 확인된 코칭의 `improved_example`에서 서버가 정한다. 클라이언트가 임의 문장을 합성하도록 허용하지 않는다. API:

- `GET /v1/analyses/{id}/sentences`
- `POST /v1/analyses/{id}/sentences/{index}/audio`

`analysis_sentence_guides`는 서버만 쓰고 소유자만 읽는다. 기본키로 문장당 음성을 캐시하며 원자적 예약·작업자 claim으로 중복 생성을 막는다. 사용자는 UTC 기준 하루 새 생성·재시도 40회, 문장당 최대 3회 제한을 적용한다. 캐시 재생에는 생성 한도를 추가로 쓰지 않는다. 한도 집계는 기록을 삭제해도 남는다.

음성은 기존 private `audio-guides` 버킷에 저장하고 5분 URL로 재생한다. 분석·세션 삭제 시 문장 음성 파일도 함께 제거한다. 활성 작업 중 삭제는 막고, 파일 삭제가 실패하면 메타데이터를 보존한다.

## 검증

API 테스트 30개, 모바일 타입 검사와 Android 번들 생성 통과. 서버 테스트는 분할·약어·소수점·최대 문장 수, 소유권·유효 인덱스, 캐시 중복 호출 차단, 작업자 중복 claim, 선택 문장·영어 기준, 생성 실패 보존, 문장 파일 포함 삭제를 확인한다.

실제 DB에서 중복 예약이 생성 횟수를 늘리지 않는 것과 클라이언트 RPC 권한 차단을 확인했다. 전체 DB 회귀 스크립트는 연결 도구의 `Invalid or expired requestState` 오류로 실행 완료를 확인하지 못했다. API 자동 테스트와 별개로 실제 기기 확인은 남아 있다.

기기 확인: 예문 듣기 → 마이크 권한 → 녹음 → 내 목소리 비교 → 다음/이전 문장 → 속도 변경 → 완료·종료. Android를 먼저 확인하고 iOS 실기기 검증은 나중에 한다.
